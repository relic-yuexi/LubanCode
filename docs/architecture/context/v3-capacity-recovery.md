## 状态与适用范围

2026-09-11 讨论定案，待实现。本文补充 v3 容量恢复策略，不表示生产链路已经接通，也不新增未经实现的事件名或字段。

本文更新主设计单 §4.38、§4.64 的范围约束：允许摘要当前 turn 内已闭合的旧 step；新 action 结果尚未发送时，允许先生成有界预览或摘要。此前“未完成 turn 一律整轮保留、只能降档工具预览”的约束不再作为唯一恢复方案。原账追加、工具配对、候选校验和原子采用约定继续有效。

## 先分清内容是否已经发送

“发送”指进入主模型请求。执行过工具、原文已经落盘，不等于结果已送入主模型；另调模型生成摘要仍是一笔模型调用，须独立计量。

| 占空间的材料 | 处理位置 | 缓存边界 |
| --- | --- | --- |
| 新 action 结果，尚未发送 | 原文落仓，首次发送前生成预览；仍过大时按整批预算摘要或选取 | 不必追改已发送前缀；新增内容会增大分母，命中率仍可能下降 |
| 已完成的旧 turn | 摘要旧 turn，保留当前任务约束与所需证据 | 有效上下文改变，可能损失前缀复用 |
| 当前 turn 内已闭合的旧 step | 摘要连续旧前段，保留最近所需消息 | 有效上下文改变，不能声称保住原缓存 |
| 最新输入、工具参数、媒体或固定提示 | 对对应材料处理，必要时拒绝请求 | 压缩无关工具结果不能解决超限 |

单条工具预览默认最多 32768 个 UTF-8 字节。多文件、状态、路径、来源标签、截断标记与换行共用这笔预算。还须给整批结果分配总预算；单条合格不代表整份请求能装下。

已发送预览在普通追加请求中保持原样。token 校正系数只更新估算，不能使旧预览重新选取截点。若确需替换已发送内容，必须生成新版本并明确提交上下文；原消息与原始材料仍保留。

## 两个例子

以下数字仅作说明，不是模型实测。

**新结果挤满请求。** 扣除输出预留及协议余量后，输入可用 100K token，旧历史占 80K。一批十个 action 返回结果，共估算 40K，尚未发送。将新结果按调用分别压缩，合计控制在 15K，下一请求约 95K。每项结果仍对应原 tool_call_id，不重跑工具，也不改旧历史。若旧历史本身已占满预算，则仍须处理旧历史。

**单个 turn 跑得太长。** 准备下一次模型请求时，step 1、step 2 已结束，工具调用与全部结果已配齐。可把这段连续前缀摘要化，保留用户原始请求及最近所需原文，再继续执行。尚未生成的下一 step 回复没有内容可保留；不得伪造。摘要替换必须覆盖闭合工具组，不能留下孤立调用或孤立结果。

摘要至少保留任务约束、已执行操作及副作用、成功/失败/未知状态、关键结论与证据引用、文件路径、未完成事项。用户原始请求通常保留；若它本身超限，须另行处理，不能暗中丢掉约束。

## 处理顺序按占用来源选择

1. 捕获结果并保存原始材料，区分捕获不完整与预览省略。
2. 为新 action 生成首次发送内容，检查单条上限与整批预算。
3. 在工具组闭合、下一请求准备边界，计量整份最终请求。输入、输出预留、协议余量与媒体占用都要入账。
4. 新结果过大，先处理新结果；旧历史过大，摘要已完成旧 turn，必要时摘要当前 turn 内已闭合旧 step。不能机械执行一条与占用来源无关的压缩阶梯。
5. 校验候选、配对与预算，保存来源和版本，提交后发布有效上下文，再准备并发送请求。冻结候选之后到达的新输入留待后续处理。

历史预览 32→16→8→4 KiB 降档保留为有损处理手段，不再列作每次 step 摘要之后的必经步骤。仅当工具预览确为超限来源、降档能产生足够收益时选择；仍沿 context.tool_previews.reduced 明确换链，普通请求不自动升档。

## 失败边界

| 失败场景 | 必须采取的处理 |
| --- | --- |
| 新结果连摘要模型也装不下 | 按文件、范围或有界分块处理，再汇总；摘要模型按自己的窗口与输出预算验容量 |
| 调用数量太多，短摘要加协议外壳仍超限 | 限制后续批次规模；已发生调用不可删掉或伪造结果，闭合后可整体摘要；仍无法组成合法请求则停止 |
| 用户正文、assistant 参数、system 或媒体本身过大 | 处理对应来源；媒体采用自身预算，必要时要求缩减输入或报错 |
| 摘要漏掉副作用或执行状态 | 校验后拒收，不能让模型误以为工具未执行而重复操作；原始证据可按引用读取 |
| 切分破坏工具配对 | 拒收候选；只在闭合边界切分，不截断工具参数、协议外壳或签名块 |
| 替换前缀后与模型思考签名约定不兼容 | 按目标 adapter/模型合同校验并构造合法请求；复制旧签名不等于合法 |
| 摘要没有严格减少占用 | 记录无收益，不采用；调整预算或停止，不能无限递归压缩 |
| 本地估算通过，服务端仍拒绝容量 | 记录失败输入，留足余量；仅重试严格更小且合法的新版本，并限制恢复次数 |
| 摘要失败、取消、校验失败或写盘失败 | 保留此前已提交上下文，不采用半成品；若旧请求已超限，阻止继续发送 |
| 新链已提交但内存投影失败 | 停止发送，按已提交链恢复，不能继续使用旧内存历史 |

原始捕获不完整时，摘要无法补回缺失内容，必须保留 incomplete 状态及原因。所有候选都失败时停止本次恢复，保留原账、结果仓、队列与失败原因；已独立提交的成功变更不回滚。

## 接线与验收

本次源码核查发现：BuildToolPreview 在 src 中只有声明与定义，普通工具返回仍以 result.content 进入运行时历史，v3 写桥也把同一全文写入 tool 消息；ReduceToolPreviews 尚无生产调用点。共用 hard trim 又按动态校正系数重裁旧结果。须先打通首次预览生成、运行时回喂与持久消息一致这条链，不能只修缓存诊断文字。

接线前须明确 step 摘要与 action 摘要的来源、身份、模型调用用途、校验及提交合同，并同步 schema、writer、reader、恢复与主循环。不得仅在内存替换文本，随后声称 v3 已采用。

验收至少覆盖：巨型单结果、整批结果超限、单个长 turn、校正系数变化、摘要无收益、工具配对、捕获不完整、provider 容量拒绝、落盘失败与提交后崩溃恢复。确认首次工具预览不超字节预算、旧预览普通追加时逐字不变、每次恢复请求严格更小且合法。缓存验收同时检查请求前缀和服务端 usage；稳定前缀不能保证服务端必然命中。
