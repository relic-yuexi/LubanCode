# 终端交互

[文档首页](README.md) · [命令与键位](commands.md) · [会话与上下文](sessions-and-context.md) · [配置手册](configuration.md) · [测试手册](testing-guide.md) · [排错手册](troubleshooting.md)

LubanCode 把终端当工作台，不当一根只进不出的管子。模型在写，输入框还能收字；工具在跑，状态仍可查看；公式到了终端，也尽量排成能读的样子。

## 1. 两种界面

启动时，程序先看 stdin、stdout 是否连着真终端。

| 场景 | 界面 |
| --- | --- |
| Windows Terminal、PowerShell、常见 Unix TTY | 彩色交互界面，带输入编辑、菜单、动画和原地刷新 |
| 管道输入、输出重定向、CI 日志 | 朴素文本，不发 ANSI 光标控制码 |
| 终端不支持彩色或主动关色 | 保留布局，换成 ASCII 标记 |

交互能力探测失败时，程序宁可少画，也不往日志里撒一地转义码。可用 `LUBANCODE_FORCE_COLOR` 调整颜色探测；完整配置见[配置手册](configuration.md)。

## 2. 输入编辑器

普通输入框支持：

- 左右移动光标，`Home` / `End` 跳到行首行尾。
- `Backspace` / `Delete` 删字。
- `↑` / `↓` 翻本次进程内的输入历史。
- 中文、emoji 与宽字符按屏幕列宽移动，不按 UTF-8 字节乱跳。
- `Shift+Enter` 在光标处插入换行；`Alt+Enter` 同义。
- 单行 slash 命令按 `Tab` 补全并打开候选菜单。

Windows Terminal 常把 `Alt+Enter` 绑成全屏切换。写多行时，用 `Shift+Enter` 最稳。

只有“整条输入是单行、首字符为 `/`”时，才按 slash 命令解析。多行正文即便从 `/` 开头，也按普通消息发送。命令全集见[命令与键位](commands.md)。

## 3. 粘贴

真终端会开启 bracketed paste。编辑器借它分清“用户敲了回车”和“粘贴内容自带换行”。

- 1000 字符以内，原样摆进输入框。多行也能继续编辑。
- 超过 1000 字符，折成 `[粘贴内容 N 字符]`。
- 光标可移到占位符两边添字。
- 退格碰到占位符，会整段删去。
- 提交时，占位符展开成完整原文。屏幕回显和模型输入拿到同一份内容。

Windows ConPTY 偶尔把一趟粘贴拆成逐键输入。编辑器会追收同一批字符，再照上面的阈值处理。

这条路也拦住“粘贴多行后逐行误执行”。管道模式不启 bracketed paste。

## 4. 流式期间继续输入

请求发出后，代理在后台跑。终端仍守着输入框。

```text
助手正文继续流出

Working 12.4s · Esc 中断
待发送 2 条
> 这里还能继续输入
```

用户按 Enter，新消息先进待发送队列。本轮收尾后，队列按先来后到送出。界面只展示最近三条，内部队列不截断。

`Esc` 或单击 `Ctrl+C` 会打断当前轮。已经排队的消息仍会接着发。连续按两次 `Ctrl+C` 则退出进程，退出码按终端惯例取 130。

流式正文与输入框不争光标。每段事件到来时，界面先把光标带回正文，写完再重建 footer 和输入框。

## 5. Footer 与状态面板

首个流事件尚未来时，状态行显示耗时与中断提示。亮色沿 `Working` / `思考中` 逐字扫过。动画线程只报状态，真正绘图仍由一把 UI 锁收拢。

输入框下方常驻 status panel。默认字段包括：

- 确认档 `confirm` / `auto` / `yolo`。
- 当前模型。
- 工作目录。
- Git 分支。
- context 百分比和 token 数。

不在 Git 仓库时，分支字段自动消失。中途切目录、换模型、改思考档，下一帧便跟着变。`status_panel.items` 可改字段与顺序，`separator` 可改分隔符。

## 6. Markdown 渲染

正文一边流，一边分段。每逢空行，渲染器收束刚写完的块，再画成终端样式。

支持的主要结构有：

- `#` 标题。
- 粗体、斜体、行内代码与删除线。
- 有序、无序列表。
- 引用。
- 围栏代码块与常见语言着色。
- Markdown 表格。
- 分隔线与链接文本。
- 行内和块级数学。

代码围栏没闭合时，渲染器先等着，不会误把里面的 `#`、`|`、`$` 当 Markdown。长回答卷出屏幕后，新段仍各自立锚；前面一处失配，不该拖垮后面整篇。

## 7. 行内数学：`$...$`

行内数学要跟文字挤在一行里，不能凭空长高。这里采用紧凑 Unicode 排版。

输入：

```latex
Euler 公式 $e^{i\theta}=\cos\theta+i\sin\theta$
```

终端尽量画成：

```text
Euler 公式 𝑒ⁱᶿ = cos ᶿ + 𝑖 sin ᶿ
```

主要转换如下：

| LaTeX | 终端近似 |
| --- | --- |
| 普通拉丁变量 | Unicode 数学斜体，如 `a` → `𝑎`、`x` → `𝑥` |
| `^2`、`^n`、`_1` | Unicode 上下标，码位存在时直接换 |
| `\theta`、`\alpha` | 常用希腊字母 |
| `\pm`、`\leq`、`\ne`、`\infty` | `±`、`≤`、`≠`、`∞` |
| `\frac{a}{b}` | 紧凑斜杠式，如 `𝑎/𝑏` |
| `\sqrt{x}` | `√𝑥` |
| `\mathbb{R}` | 能映射时用数学字母，如 `ℝ` |
| `\text{...}`、`\operatorname{...}` | 保留直立文字 |

Unicode 并没有给每个字母、希腊字母都配齐上标。缺码位时，渲染器保留普通字符或退回可读写法，不拿相似字符硬顶。

行内公式适合短式。分式、根式、矩阵一多，就改用 `$$...$$`。

## 8. 块级数学：`$$...$$`

块级公式可以长高。LubanCode 不把 LaTeX 变成图片，也不要求终端支持 SVG。它先把语法树排成二维字符盒，再用 Unicode 线条和终端字符画出来。

例如：

```latex
$$
\frac{-b\pm\sqrt{b^2-4ac}}{2a}
$$
```

会得到近似布局：

```text
     ─𝑏 ± ╭──────────
          │ 𝑏² − 4𝑎𝑐
     ─────────────────
            2𝑎
```

字形随终端字体略有出入，行列关系却保住了。支持的结构如下。

### 8.1 基础结构

| 语法 | 能力 |
| --- | --- |
| `\frac{a}{b}` | 上下堆叠分式，横线按较宽一边伸展 |
| `{a\over b}` | 传统 `\over` 分式 |
| `\sqrt{x}` | 根号与上横线 |
| `\sqrt[n]{x}` | 带根指数 |
| `x^2`、`x_i`、`x_i^2` | 上标、下标、双脚标；短脚标优先压成 Unicode |
| `\sum_{i=1}^n`、`\prod` | 求和、连乘及上下限 |
| `\limits` | 把上下限摆到大型算子上下 |

### 8.2 括号与符号

`\left` / `\right` 会按内容高度拉伸圆括号、方括号、花括号和竖线。`\right.` 可做空右界，适合方程组。

常见关系、集合、逻辑、箭头与希腊字母会换成 Unicode，例如 `\perp`、`\subset`、`\Rightarrow`、`\cap`、`\cup`、`\emptyset`、`\leq`、`\theta`。

`\quad`、`\,` 等间距命令会留出适量空白。终端没有 TeX 那般细密的弹性胶水，故而只求疏密清楚。

### 8.3 矩阵、数组和方程组

支持 `matrix` 与 `array` 环境：

```latex
$$
\left\{
\begin{matrix}
x=a+r\cos\theta \\
y=b+r\sin\theta
\end{matrix}
\right.
$$
```

行用 `\\` 分开，列用 `&` 分开。`array` 的列格式参数会读入；终端排版以内容对齐和可读为先，不完整复刻 TeX 的全部列间距规则。

这些实式都已列入回归实验：二项乘积、勾股根式、分式乘方、异分母加减、双曲线、分母有理化、n 次根、求根公式、点斜式、参数方程组、概率公理、四种平均数不等式。

### 8.4 不支持时怎么办

盒式排版器不是完整 TeX 引擎。它不执行宏，不加载宏包，也不跑任意命令。遇到未知命令或结构时，原则只有两条：

1. 能保住文字，便保住文字。
2. 整块解析不了，便退回原始 LaTeX，绝不悄悄吞掉。

终端太窄时，长行会按显示宽度裁切或交给终端折行。公式若要精确出版，仍该交给 LaTeX、KaTeX 或 MathJax；这里解决的是“在命令行里看懂”。

## 9. 为什么原来的公式没渲染

最常见有四宗：

1. 模型输出了字面量 `$$`，旧版本只认 Markdown，不认数学块。
2. 行内公式跨了多行，分隔符没成对。
3. 公式藏在代码围栏里。代码块按源码展示，本就不渲染。
4. 运行的仍是旧 `lubancode.exe`，源码虽改，Release 可执行文件没重建。

现版同时认 `$...$` 与 `$$...$$`。要试公式，先确认 `lubancode --version`，再用完整成对的分隔符。块式写法最稳：

```markdown
$$
\frac{x^2}{a^2}-\frac{y^2}{b^2}=1
$$
```

## 10. 工具转录

每次工具调用在转录里占一条。运行时亮黄灯，成功换绿灯，失败换红灯。开始态和结束态共用原位，不各留一条。

默认紧凑模式只摆名称、摘要和短结果。按 `Ctrl+O` 可切详细模式，整组工具条目按新档重画：

- 完整参数 JSON。
- 更多输出。
- 完整 diff 或截断提示。
- 子代理内层工具。

活动轮次也存一份转录快照。模型尚未答完时按 `Ctrl+O`，界面照快照重放，不会把刚才的工具结果弄丢。

## 11. 焦点查看

空输入框按 `Tab`，进入工具条目焦点态，并选中最近一条。

| 键 | 动作 |
| --- | --- |
| `Tab` | 往旧条目走 |
| `Shift+Tab` | 往新条目走；只在焦点态如此 |
| `Ctrl+E` | 查看当前条目全文；无焦点时看最近一条 |
| `Ctrl+E` 或 `Esc` | 从全文页返回 |
| `Esc` 或 `Enter` | 退出焦点态，回输入框 |

非焦点态下，`Shift+Tab` 始终轮换确认档。流式输出正忙时，焦点浏览键暂不响应，免得正文改写与查看页撞在一起。

完整输出也有内存上限。极大的工具结果在收录时最多保留 64 KiB；这和模型上下文里的工具结果截断是两套边界。

## 12. Diff

`write_file` 和 `edit_file` 会先画 diff，再按确认策略落盘。

- 新增行铺绿底，删除行铺红底。
- 上下文带真实行号。
- 长段无变化内容折起。
- 超宽行按显示列裁切。
- C/C++、Python、JavaScript/TypeScript、JSON、Shell/PowerShell、Rust、Go 支持 token 着色。
- 不认得的扩展名保持素色，不乱猜语言。

背景色套在外层，关键字、字符串、数字、注释只换前景。每行末尾统一复位，故而不会剩下半屏色块。

`edit_file` 若精确匹配失败，会再试统一换行和忽略整块缩进。候选不止一处且没开 `replace_all`，便停手报位置。

## 13. Todo 与子代理状态

`todo_write` 第一次落计划，显示 `todo_write(N 项)`。同一轮改状态时，显示 `todo_update(N 项)`。

项数没变，界面抓住原计划块就地更新，只点亮有变化的项。计划增删了条目，另起更新块。这样旧块不会突然长高，盖住已经写出的正文。

子代理各占固定三行：状态摘要、耗时/token/工具数、展开提示。结束后耗时定住。`Ctrl+O` 可看更深的内层工具记录。

## 14. `ask_user`

模型遇到会改变实现方向、又无法从仓库查明的选择时，可调用 `ask_user`。一次可问一至四题；每题给二至四项，可单选，也可多选。末尾总补一项“自己填写”。

真终端用原地菜单：

- `↑` / `↓` 移动。
- `Space` 勾选多选项。
- `Enter` 提交。
- 移到“自己填写”后直接打字，`Backspace` 删除。
- `Esc` 取消。

管道与单发模式不注册 `ask_user`。无人守着 stdin 时，程序不能干等。

## 15. 工具确认

确认提示认三种回答：

| 输入 | 结果 |
| --- | --- |
| `y` | 只准这一次 |
| `a` | 准许，并可把工具名写入项目 `.lubancode/settings.local.json` |
| `N`、`Esc` | 拒绝 |

非焦点态按 `Shift+Tab`，在 `confirm`、`auto`、`yolo` 三档间轮换。状态面板会当场显示新档。

确认只管“是否执行”。工具本身仍要校验路径、参数、超时和输出上限。`yolo` 不是绕过这些护栏。

## 16. 图片输入

可在普通消息里写 `@路径`，也可用 `/image`。支持 PNG、JPEG、GIF、WebP，单张上限 5 MiB。程序从文件头校验格式与尺寸，再按当前协议编码。

路径有空格时要加引号。一次可带多张图。模型本身若不支持视觉，服务端会报错；终端只负责把合法图片送出去。

## 17. 会话恢复

裸敲 `/resume` 会列出本目录最近会话。`↑` / `↓` 选择，`Enter` 恢复。熟悉编号或 id 时，也可直接写 `/resume 1` 或 `/resume <id>`。

终端按原顺序重放：

- 用户正文。
- 助手 Markdown。
- 工具调用与结果摘要。
- 上下文压缩标记。

恢复后继续输入，新消息仍追加到原 JSONL。详见[会话与上下文](sessions-and-context.md)。

| 键 | 空闲编辑 | 流式期间 | 菜单/焦点 |
| --- | --- | --- | --- |
| `Enter` | 提交 | 加入待发送队列 | 选择或退出焦点 |
| `Shift+Enter` | 插换行 | 插换行 | - |
| `Tab` | slash 补全；空行进焦点 | 暂不浏览 | 往旧条目 |
| `Shift+Tab` | 切确认档 | 切确认档 | 往新条目 |
| `Ctrl+O` | 切紧凑/详细 | 切紧凑/详细并重放活动快照 | 同左 |
| `Ctrl+E` | 看最近工具全文 | 暂不浏览 | 看当前工具全文 |
| `Esc` | 清输入或退查看页 | 中断当前轮 | 取消/返回 |

| `Ctrl+D` / `Ctrl+Z` | EOF 退出 | - | - |

## 19. 排错

**公式仍显示源码**

先看分隔符是否成对，公式是否藏在代码围栏。再看运行版本。块级公式用独占行的 `$$` 最稳。

**出现 `^[`、`[2K` 一类字样**

stdout 多半不是程序认得的真终端，或终端能力探测有误。先试 `--help` 的朴素输出，再检查颜色和 ConPTY 环境。

**中文光标错位**

换一款支持 East Asian Width 的等宽字体。终端若把同一字符算成不同宽度，应用无法完全补救。

**粘贴后立刻提交**

确认终端启用了 bracketed paste。Windows Terminal 自定义键位或旧版 ConPTY 也可能拆散事件。

**详细模式看不全**

用 `Ctrl+E` 看单条全文。若仍有截断，说明结果已撞上 64 KiB 转录上限；原始命令日志或目标文件才是全本。
