# SDK 子 Agent 首批合同

状态：实现前合同；尚无公开子 Agent 入口。SDK 完整化下一笔先接受管前台派工，再接后台与 Action 扩展。本笔验收不过，不勾子 Agent 完整化，也不替 CLI 功能平齐。

## 公开什么

宿主逐场显式开启，默认关。首笔只准模型派前台子任务，主回合等子任务退出再续跑。子任务类型、工具名单、深度与并发帽由宿主冻结，模型不能改场身份、后端所有权或工具许可。

公开配置与查询只收标准库值及已安装 SDK 类型。宿主不包含 `AgentTool`、`AgentProfile`、`TrajectorySubagentBridge` 或 TaskLedger。具体结构随实现 PR 定稿；配置摘要须落场账，并接入有效 system 的 host binding。同 ID 恢复沿原计划；显式变化拒开，旧无计划场继续关闭。

`background`、隔离 worktree、恢复未完子任务、Lua/Package/Detached 均后置。模型显式请求尚未开放的模式，应在注册任务、起线程或建 worktree 前明报不可用。CLI 原模式与工具面照常保留。

## 谁拥有

复用 `AgentTool`、协调器与现有前台派工路径，不能在 SDK 回调里另建一套公开 Session 拼子循环。现有 `RunSubagentTask` 会直接装配内部 Agent；实现时须把这处资源与 Agent 的所有权收进共用执行对象，供 SDK 和原宿主共同使用，不能只把旧裸引用包进公开选项。

每场持派工 owner、冻结工具计划与后端借用。首笔父子串行，子任务借本场后端；不要求可注入 Backend 支持并发或复制。后端工厂与并行孩子另笔开放。ToolRegistry、MCP client 和扩展回调的真实拥有者必须活到所有借用退出；协调器存活不证明这些借用仍有效。

现有前台路在父工具调用里同步执行 `RunSubagentTask`，父循环等它返回；只读并行名单也只含 `read_file`、`search`，不含 `agent`。借同场 Backend 有这条串行依据，不靠 Backend 内锁兜底。嵌套孩子仍须守派工深度与活任务帽；活任务帽统计台账活态，不等于同时发请求数量，也不证明真实线程退出。

子任务沿父场 cwd，可在同一已有项目运行。另开工作目录不是派工前提。Explore 一类只读工具面必须收窄；自定义工具须逐项显式准入。首笔不得把父场 Memory 写入/召回报告模块直接给子任务调用；这些模块绑定父 operation/turn，跨子账继承须另有合同和真实身份校准。

## 身份、权限与落账

根 Session、父 operation/turn/action 与子 task/run/turn 分别落账；模型 call ID 只作线协议配对，不冒充真实 action。父账记录派出和实际子账终态引用；子账保存完整执行事实。公开子任务报告返回 owned 身份、状态和冻结 preview，正文与工具原件仍留执行端。Full 仍须 Node 许可与本场参数双开。

审批与取消沿真实子 action 转发，子任务不得自行提升权限。父场当前策略与撤权须在子工具实际执行前检查；不能只靠派出时快照继续放行。关闭期间的新派工拒绝；主场取消须传到正在跑的子模型与工具。

恢复要核冻结计划、父子引用、子账身份和最终采用事实。完结子任务不得重复执行；合法中断沿 SDK 未知态停住，不能从一条任务终态猜工具副作用已经确认，也不能默默再派一遍。坏账、跨场引用和重哈希冒领须拒开。公开查询不能修账或触发派工。

## 怎么关场

Close 先关派工准入、广播取消，再等子调用和真实工作线程退出；随后关子 writer、主 writer 与受管执行资源，最后释后端、MCP 和工具 owner。这里只定借用先退出，具体析构次序随共用 owner 的实现逐项核准。

不能把 `JoinAllBounded` 的 detach 退路当作 SDK 关场完成：现有冻结运行态仍有工具表与 Explore 表裸借用。SDK 首笔不准借用越过 Close 返回；做不到应停在内部合同修复，不能先交公开入口。文件系统、网络和宿主回调未许诺固定墙钟上限。

## 实现前置门与分批

先修中立通路，再接公开 SDK。下面四道门尚未实现，不能拿本合同当现成接线。

1. **共用执行 owner。** `RunSubagentTask` 目前另造任务工具表、`SubagentTraceBackend` 包装，再直接构造内部 Agent。首笔把包装、任务表、Agent 与回合绑定一同收进共用执行 owner；表中转发工具仍借原件，父场资源 owner 须罩住这些借用。不能照主场新建 MCP/Backend，也不能只让协调器活着便释放原表。Memory 模块与其他逐 operation 回调不得随父表自动继承；代理引用解析也须按子工具名单收窄。
2. **异步审批与取消。** 子 Agent 的 `AgentSubagentHooks` 现在只有同步确认口，SDK 走 `on_tool_confirm_async`。先补中立异步转发，保留真实子 task/turn/action 归属，再接同场审批 future、当次权限裁定与取消。不能把 SDK 阻塞等待塞进旧同步确认口便称接通。`AgentDispatchTool` 当前忽略 `ToolExecutionContext`，外部取消靠每回合 `Hooks.cancel` 进入现有 `CancelChain`；新装配须明确接这根旗，并在子调用退出后撤掉借用。
3. **严格关场。** 前台无需另起执行线程；取消合流与协调器监督线仍有线程。SDK 的收口须等这些真实借用退出，不只等 TaskLedger 状态变终态。`JoinAllBounded` 和监督器析构各有 detach 退路，须先补 SDK 使用的严格收线程路径，CLI 旧关场语义另保。`ScopedTurnBindings` 只恢复临时接线，不持执行资源，也不替线程收柄。
4. **耐久父子回执。** 现有子账可复用真实 `subagent.spawn.requested`、`subagent.linked` 与独立 V3 writer；开场引用仍有旧路回退，`Finish` 只返 hash、失败返空，TaskLedger 快照也不是公开耐久报告。先补严格身份与 typed 收口回执：子账确认、父账终态引用、父工具结果采用须分别核准；落盘未知须停父循环，不能洗成普通工具错误再送模型。冻结计划与报告归本场持有，恢复先验父子身份、引用次序与原件，Close 后只查 owned 值。展示用 `WalkSessionTree` 会容忍缺件，也不能代替严格恢复 gate。

实现按三段收：第一段拆两笔，先收共用 child 执行 owner，再补中立异步接线，CLI 回归不变；第二段补前台准入、严格关闭与父子回执，先用内部真实派工验；第三段才开默认关闭的 SDK 入口、冻结计划和只读查询，并跑安装消费与多场隔离。每笔另核源码与远端证据；前两段完成仍不算 SDK 子 Agent 交付。

## 远端验收

真实公开 Submit 派子任务；安装后 consumer 只用公共 SDK。每场要验默认关闭、显式开启、子后端请求与工具执行、审批拒绝/撤权、取消/Close、父子终态引用、preview 与完整工具结果留存、计划恢复和坏账拒开。

同一项目两场、不同项目各一场，交错派工并复用模型 call ID，核后端、模型、权限、取消、报告与工作目录不串场。关闭其中一场，另一场仍能跑；第一场实际线程与工具借用必须收尽。派工注册失败、线程创建失败与资源装配异常须零悬空 owner，并保留真实失败账。

CLI 旧子 Agent 册、共享执行/审批/结果册与安装后 SDK consumer 同跑三平台；ASan 钉实际来源与非零用例。仅文档检查或内部单测通过，不算新宿主验收。本地不配置、编译或跑原生；实现与测试提交远端 CI。
