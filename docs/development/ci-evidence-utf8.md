# CI 证据文本按 UTF-8 读取

基线 `a23f98e6`。Windows 全量原生 789 项通过；Named、Journal、ModelInput
三道后置纯数据检查随后失败。它们读取 `ci.yml` 时未填编码，Python 3.12
转用 cp1252，遇到原 UTF-8 字节报错。三份 extractor 原件已生成，整轮仍记失败。

本笔只改这三份纯数据测试：源码 YAML 与生成的 JSON 都显式按 UTF-8 读取。
字节保存、失败材料、注册名册、CASE、断言、截止预算和 workflow 不改。
不设全局 locale，不容错替换坏字节，不删中文，也不绕过失败检查。

文本仍由原路径与原文件拥有。读取时解码，原件按字节保存；临时目录仍由原
fixture 收场。坏 UTF-8 继续拒绝，不能把无法解码的原件报成通过。

验收跑原三份纯数据测试，另用 cp1252 默认读取代理重放同批测试，核修后无需
系统编码支持。新 C++ 组合仍须交本源远端 CI；本地不编译、不跑原生。
失败轮与其首失败原件留存，不改封账，不借全量原生通过冒称整轮通过。
