# 后台子代理线程启动收口

状态：候选实现；原生证据只取远端 CI。本笔不公开 SDK 子 Agent，也不收 detach 后工具表、hooks 与父账借用寿命。

后台任务先注册 Running，再备子账和隔离房。旧路直接起线程，随后才塞进协调器线程表。线程创建失败会留下活态任务；活线程入表分配失败还会触发 `std::terminate`。

协调器改为先预留稳定线程条目，再调用线程工厂。预留与 `RequestClose` 共用同一把门：预留先落，关闭便接管这次启动；关闭先落，后到启动明确拒绝。工厂、用户 capture 销毁和 join 都在锁外。关闭先等 startup/reaping 交接，再沿既有退出回执等待窗执行 join/detach；新请求不能越过 closing。交接等待与回执之后的 capture 析构、join 不承诺硬截止。测试工厂须返回一条 joinable 线程或抛异常，不得在启动回调内重入同一协调器关闭。

启动尚未成功时，派工侧守住台账、子账与房务。分配或工厂抛错，任务只落一笔真实失败终态，退并发槽；已有子账调用 `Finish(false, "thread_start_failed")`，隔离房沿现有房务规则收尾。closing 拒启也收同一份资源，错误原因另列。成功交接才解除失败守卫；原成功、取消、结果回流规则照旧。

验收在现有 Agent 单测册补确定场景：线程工厂抛 `system_error`/`bad_alloc`，失败后再派一场仍可成功；子账只有一次失败结尾；隔离房有收尾回执；closing 先落时工厂不调用；关闭与已接纳启动交错时关闭真正接住线程；退出 capture 重入协调器时不困在锁内。原后台成功与取消册仍跑。三平台全量与 ASan 取同一源码头，不借旧绿、不随机耗尽系统线程。

本笔只包任务注册后至成功线程交接前。成功交接后，旧 worker 的隔离表装配、结果收账和子账异常补收另开一笔；不据此称整条后台执行已收异常。
