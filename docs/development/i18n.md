# 界面多语言(i18n)

[文档首页](../README.md) · [功能总览](../reference/feature-index.md) · [命令手册](../reference/commands.md) · [配置手册](../reference/configuration.md) · [Provider 目录](../features/providers/catalog.md) · [扩展指南](../features/extensions/README.md) · [架构说明](../architecture/README.md)

lubancode 的界面文案走两套来源:内置的中文、英文编译进程序,开箱即用;其余语言靠**外部 JSON 语言包**扩展,不碰源码、不重编译。本文核实自 `src/cli/i18n.hpp` 与 `src/cli/i18n.cpp`。

> 这里只管"给人看的界面文案"。发给模型的一切(系统提示、工具描述、tool_result)不走 i18n,那是模型自己的事。

## 一句话机制

界面每处文案都拿一个**键**去查表,`tr(key)` 按这条链找,命中即停:

```
当前语言(用户包 → 内置表)
  → zh-CN(用户包 → 内置表)
  → key 本身
```

- **内置两种**编译进程序:`zh-CN`(全量)、`en`(核心键,未覆盖的自动回退中文)。
- **用户语言包**压过内置同名键;`ja` 这类新语言整表都来自语言包。
- 三层都查不到,就直接显示 `key` 本身——宁可见到 `error.api_key_missing` 这种原始键,也不显示空串。

## 语言包放哪、长什么样

- 路径:`~/.lubancode/languages/*.json`(Windows 是 `%USERPROFILE%\.lubancode\languages\`)。
- 文件名即语言码:`ja.json` → `ja`。
- 内容是**平面键值对**(顶层一个 JSON object,值必须是字符串):

```json
{
  "language.name": "日本語 (ja)",
  "banner.hint": "質問を入力して Enter で送信",
  "cmd.clear.done": "会話履歴をクリアしました"
}
```

- `language.name` 可选:自报家门,显示在语言选择列表里;不写就用语言码本身。
- 启动时扫一遍目录。坏 JSON、顶层不是 object、值不是字符串的,记条警告**整文件跳过**,绝不阻断启动。

## 添加一门新语言

以日语为例,建 `~/.lubancode/languages/ja.json`,翻译你想翻的键即可。**没翻到的键自动回退中文**,所以可以先翻一部分就上线,剩下的显示中文:

```json
{
  "language.name": "日本語 (ja)",
  "banner.hint": "質問を入力して Enter で送信",
  "cmd.clear.done": "会話履歴をクリアしました",
  "cmd.exit.hint": "exit で終了、/help でコマンド一覧"
}
```

重启后,`ja` 会出现在:

- 初次配置向导的语言选择里;
- `/language` 命令的候选列表里;
- `config.json` 的 `language` 字段可取值里。

## 覆盖内置措辞(不改代码的口子)

文件名撞内置语言码时,按**键**覆盖内置同键:

```json
// ~/.lubancode/languages/zh-CN.json
{ "cmd.clear.done": "history 已清" }
```

这样 `zh-CN` 下该键显示你的说法,其余键照旧内置。`en.json` 同理,给英文缺键补译或改措辞都行。

## 键名从哪找、怎么写

- 全量键名以 `src/cli/i18n.cpp` 里的 `kZhCN[]` 表为准(它是完整清单,`en` 是子集)。照着逐条翻译即可。
- 键名规矩:分层小写点号,如 `help.slash.sessions`、`status.mode.confirm`、`confirm.prompt`、`error.api_key_missing`。
- 占位符用 `{0}` `{1}` … 按序填,原样保留在译文里。`{数字}` 以外的花括号(比如帮助文本里的 JSON 示例)不动。

## 怎样选语言

优先级从高到低,`language` 字段参与四级合并:

1. `LUBANCODE_LANG` 环境变量;
2. 项目级 `.lubancode/config.json` 的 `language`;
3. 全局 `~/.lubancode/config.json` 的 `language`;
4. 内置默认:空 = 跟系统。

系统探测:Windows 按 `GetUserDefaultUILanguage`,其余平台看 `$LANG`;`zh` 前缀归 `zh-CN`,`en` 前缀归 `en`,认不出归 `zh-CN`。

会话内可用 `/language` 即时切换,作用于命令说明与界面,可选写回配置。裸敲 `/language` 列出可选语言(内置两种 + 扫到的语言包),带语言码直接切。

## 边界与排错

| 现象 | 原因 |
| --- | --- |
| 新语言不出现 | 文件不在 `languages/` 下,或扩展名不是 `.json`,或文件名/目录拼错。 |
| 坏语言包导致启动告警 | 警告打印后跳过该文件,不影响启动;看警告里点名的文件即可。 |
| 部分文案仍是中文 | 该键在语言包里没翻到,按回退链落到 `zh-CN`。补上同名键即可。 |
| 覆盖内置不生效 | 文件名须正好是 `zh-CN.json` / `en.json`,且键名与内置一致。 |
| 语言切了,某些提示没变 | 极少数文案在语言设置之前就已定型,属已知取舍;重启或再触发一次即可。 |

语言是进程级全局状态,`SetLanguage` / `LoadLanguagePacksFromDir` 只在主线程(启动、命令之间)调用;`tr` 内部有锁,监听线程并发读安全。语言包永远不阻断启动——它是锦上添花,不是前置依赖。
