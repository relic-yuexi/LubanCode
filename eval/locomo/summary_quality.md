# 摘要质量双库对照(记忆写入侧改进单 §1.2)

同一批 LoCoMo 材料(十场对话 272 个 session),旧/新抽取 prompt 各灌一套库,
同题集(1986 题,可定位 498)跑 E1 检索对照。两库同走真路:cheap 路由
(ccmoon/gpt-5.6-sol,温度 0,推理档 medium——与 E2 同口径)发
RunMemoryExtraction,再走正门 EnqueueSave→worker 落盘→BuildTurnContext
生产召回路(Options 生产默认)。

- 旧 prompt = origin/main 版(无"成色"节);
- 新 prompt = 本单批二版(summary 按要点写:谁/何时/何地/做了什么,实体与
  日期用原词进 summary;title 必含核心实体;长度上限不动)。
- 映射两库同规则:候选被"不收清单"拦空时(聊天材料 272/272 如此)用回合
  summary 派生 title、retrieval_terms 做 keywords,content 一律 session 转写,
  occurred_at 一律 session 日期——隔离出"摘要质量"单变量。
- 逐题排级账:trace.json 旧/新各一份(本地 D:/locomo_e2_ws/extract_{old,new},
  gitignore 语义,不进 git);token 账同目录 .usage.json。

## R@k 对照(分母=可定位题)

| 类别 | 可定位 | R@1 旧→新 | R@3 旧→新 | R@5 旧→新 |
|---|---|---|---|---|
| multi_hop | 65 | 0.323 → 0.338 | 0.523 → 0.446 | 0.662 → 0.646 |
| open_domain | 367 | 0.597 → 0.703 | 0.774 → 0.847 | 0.831 → 0.880 |
| single_hop | 53 | 0.208 → 0.283 | 0.434 → 0.491 | 0.528 → 0.642 |
| temporal_reasoning | 13 | 0.385 → 0.308 | 0.846 → 0.846 | 0.923 → 0.846 |
| **合计** | 498 | **0.514 → 0.600** | 0.707 → 0.757 | 0.779 → 0.823 |

**合计 R@1 +0.086,过验收线(≥+0.03)。** 主要增益在 open_domain(+0.106)
与 single_hop(+0.075)——要点式摘要把实体原词送进了 title/summary 加权词。
temporal(n=13)与 multi_hop 的 R@3 有回落,单桶小样本噪声带内,合计四桶
不退。

参照系:官方摘要灌库(E1 在档基线)合计 R@1 = 0.612。真抽取路旧 prompt
掉到 0.514(120 字回合总结比 500 字官方摘要词面薄),新 prompt 收回到
0.600——距官方摘要库还差 0.012,基本追平。

## 抽取成本对账(cheap 路由,272 session 各一发)

| 库 | 请求数 | 失败重试 | input | output(含推理) |
|---|---|---|---|---|
| 旧 prompt | 274 | 2 | 356,724 | 44,437 |
| 新 prompt | 272 | 0 | 430,733(+21%) | 47,156(+6%) |

新 prompt 的"成色"节加长约 270 字,系统提示变长推高 input;output 上限
(1500 token/发)不变,涨幅 6%。没有翻倍烧钱。

## 结论

1. 结构化要点(实体+日期进摘要)是检索词面的净增益:R@1 +0.086,四桶
   合计不退,过线,保留。
2. 聊天材料下生产抽取的"不收清单"正确拦空全部候选——真产物是回合
   summary;它的成色直接决定检索天花板,本对照量化了这件事。
3. 负结论不适用:没有观察到"要点式摘要丢叙事词压低检索"的形态
   (content 转写同在索引里,叙事词没丢)。
